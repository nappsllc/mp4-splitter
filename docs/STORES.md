# Publishing to the Microsoft Store

Every tag builds an unsigned `.msix` for the Store (the `msix` job in
`.github/workflows/release.yml`). Microsoft signs it when it passes certification.
Nothing here uploads anything by itself: submitting is done by hand in Partner Center.

## In-app updates and the Store

An MSIX package never updates itself. The app detects that it runs from a package
(`update::is_msix`): it has no daily check, no **Check for updates**, and Settings says
updates come from the Microsoft Store. The plain exe from GitHub Releases updates itself
as usual, and the two don't affect each other.

Keep `SHA256SUMS.txt` in `release.yml`. The exe's updater refuses a release without it, and
never edit or re-upload an asset after publishing without regenerating it.

## What to copy from Partner Center

These three values, and only these, are placeholders in the repository. They are not
secrets. Find them in Partner Center under **Apps and games**, your app, **Product
management**, **Product identity**, after reserving the name. Copy them exactly.

| Repository variable | Partner Center field | Example shape | Placeholder until then |
|---|---|---|---|
| `MSIX_IDENTITY_NAME` | Package/Identity/Name | `12345PowerNapps.MP4Splitter` | `PLACEHOLDER.MP4Splitter` |
| `MSIX_PUBLISHER` | Package/Identity/Publisher | `CN=XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` | `CN=PLACEHOLDER-FROM-PARTNER-CENTER` |
| `MSIX_PUBLISHER_DISPLAY` | Package/Properties/PublisherDisplayName | `PowerNapps` | `PLACEHOLDER Publisher` |

Set them in GitHub under **Settings**, **Secrets and variables**, **Actions**, **Variables**.
Set all three or none: `msix.ps1` stops on a partial set.

Until they are set, the package is named `...-x64-PLACEHOLDER.msix`, stays a workflow artifact
for testing, and is left off the GitHub release. Once they are set, the next tag attaches
`mp4-splitter-<version>-x64.msix` to the release.

## First submission

1. Create a Partner Center account: <https://partner.microsoft.com/dashboard>.
2. Reserve the name **PowerNapps MP4 Splitter**. If that exact name isn't available, tell
   whoever maintains this repository: the manifest's `DisplayName` must match the reserved name.
3. Copy the three values above into the repository variables.
4. Push a version tag, and download `mp4-splitter-<version>-x64.msix` from the release.
   Package versions must keep growing: the Store refuses one that isn't higher than the
   last, so a package needs a new tag rather than a rebuild of an old one.
5. Create a submission and upload the package. Fill in:
   - **Privacy policy URL**: <https://github.com/nappsllc/mp4-splitter/blob/main/PRIVACY.md>
   - **Listing**: description, and screenshots (`docs/splitter-dark.png` and
     `docs/splitter-light.png` are ready to use).
   - **Age rating** questionnaire: no user-generated content is shared, nothing is
     collected, and the app has no online features.
   - **`runFullTrust` justification**: "A desktop video tool: it opens the video files the
     user picks, plays them through Media Foundation and writes the cut pieces next to them."
6. Submit for certification.

The package's Store icons are in `packaging/icons/msix/`, generated by
`packaging/icons/make-icon.ps1`.

## Building and trying a package locally

Needs the Windows SDK (`makeappx.exe`):

```powershell
cargo build --release
powershell -File packaging\windows\msix.ps1
```

Without the variables it builds with the placeholders and says so. With Developer Mode on,
try it without signing, then remove it again:

```powershell
Add-AppxPackage -Register dist\stage-msix\AppxManifest.xml
Get-AppxPackage PLACEHOLDER.MP4Splitter | Remove-AppxPackage
```
